# 속성 기반 감성분석(ABSA) 라벨 가이드 (의류 한정, 3단계) — 1차 확정 (2026-10-08)

이 문서는 Gemini 프롬프트(`review_analysis/absa.py`)와 사람이 직접 작성·검수하는 평가셋이 **같은 기준**을 쓰게 하려는 것이다.

**1차 확정 사항 (2026-10-08, 사용자 승인):** 속성 10개 그대로, 3단계 감성, 평가 표현 없는 사실 서술은 **미언급**(중립 아님), 중립은 '보통/무난/그저 그렇다' 평가이거나 장단점이 같은 비중일 때만. 이 기준이 `absa.py`의 프롬프트(`VERSION = 'v1'`)에 반영되어 있다.
평가셋을 작성하다 애매한 사례가 쌓이면 이 문서를 고치고 `VERSION`을 올린다.

## 1. 출력 형식
리뷰 하나에서 **리뷰가 실제로 평가한 속성만** 뽑고, 속성마다 감성 1개를 붙인다.
```
[{"aspect": "재질·촉감", "sentiment": "부정"}, {"aspect": "배송", "sentiment": "긍정"}]
```
- 같은 속성은 리뷰당 한 번만 쓴다. 한 속성에 긍정과 부정이 섞이면 전체 뉘앙스를 따른다(결정이 안 되면 `중립`).
- 근거 문장(evidence span)은 운영 단계에서 추가한다(현재 시험에는 없음).

## 2. 속성 목록 (10개)

| 구분 | 속성 | 포함하는 것 | 예시 |
|---|---|---|---|
| 상품 | 재질·촉감 | 원단 종류, 두께, 촉감, 보온성, 비침 | "생각보다 얇고 까슬거려요" |
| 상품 | 사이즈·핏 | 사이즈 정확도, 길이, 품, 신축성 | "정사이즈인데 어깨가 좀 끼네요" |
| 상품 | 색상·디자인 | 색감(사진과 차이), 디자인, 스타일 | "사진보다 어두워요", "핏이 예뻐요" |
| 상품 | 품질·내구성 | 마감, 봉제, 올 풀림, 보풀, 튼튼함 | "한 번 입고 솔기가 터졌어요" |
| 상품 | 가격·가성비 | 가격 대비 만족, 비싸다/싸다 | "이 가격에 이 정도면 만족" |
| 상품 | 냄새 | 새 옷 냄새, 퀴퀴함, 화학 냄새 | "곰팡이 냄새가 나요" |
| 상품 | 세탁·관리 | 세탁 후 변형, 물빠짐, 관리 편의 | "한 번 빨았더니 줄었어요" |
| 서비스 | 배송 | 배송 속도, 배송 중 문제 | "주문 다음 날 도착" |
| 서비스 | 포장 | 포장 상태, 박스·비닐, 구김·오염 | "비닐이 찢어져 왔어요" |
| 서비스 | 교환·환불·CS | 교환/반품 절차, 고객센터 응대 | "반품 처리가 빨랐어요" |

- **상품 속성과 서비스 속성은 집계할 때 구분**한다(상품 문제는 MD/제조, 서비스 문제는 물류/CS 담당).
- 위에 없는 내용(예: 모델 착용 사진, 사은품, 브랜드 이미지)은 **뽑지 않는다**. 필요하면 속성을 추가하는 것을 결정한다.

## 3. 감성 3단계

| 감성 | 기준 |
|---|---|
| 긍정 | 그 속성에 만족/칭찬을 분명히 표현 |
| 부정 | 그 속성에 불만/문제를 분명히 표현 |
| 중립 | 그 속성을 평가했지만 "보통/무난/그저 그렇다", 또는 장단점이 같은 비중으로 섞임 |

- **평가 표현이 없는 단순 사실 서술**("택배 박스에 담겨 왔다", "비닐에 담겨 있었다")은 **미언급**으로 본다(중립이 아님). (1차 확정) 시험 결과 Gemini와 합성 리뷰 정답이 가장 많이 갈린 곳이 이 경계였다.
- **미언급은 출력하지 않는다.** "언급 안 함"과 "중립"을 섞지 않는다.

## 4. 판단이 헷갈리는 경우

| 경우 | 처리 |
|---|---|
| 반어("포장이 너무 완벽해서 옷이 다칠 뻔했네요") | 실제 뜻을 따른다(여기서는 포장 긍정) |
| 부정 표현("나쁘지 않아요", "생각보다 괜찮네요") | 약한 긍정. 확실하지 않으면 중립 |
| 기대 대비("사진보다 별로") | 부정 |
| 비교("전에 산 것보다 두꺼워요") | 문맥상 좋은지 나쁜지로 판단 |
| 한 문장에 속성 둘("배송은 느리지만 옷은 예뻐요") | 속성마다 따로 |
| 별점만 높고 본문이 없음 | 뽑을 속성 없음 |
| 오타·ㅋㅋ·줄임말 | 의미로 판단 |

## 5. 평가셋 작성·검수 (사람이 직접)
- **법적 이유로 실제 리뷰를 복사하지 않는다**(`docs/korean-review-crawling-legal-notes.md`). 말투와 유형만 참고해 **새로 작성**한다.
- 규모: 200~300건. 속성별 최소 25건 언급(서비스 속성 포함), 감성은 속성마다 긍정·부정·중립이 모두 들어가게 한다.
- 말투 다양화: 짧은 반말, ㅋㅋ/ㅠㅠ, 오타, 정중한 장문, 반어, 줄임말, 복합 속성.
- 라벨은 `docs/absa_eval_template.csv`의 **긴 형식**(리뷰 1건에 속성 1행)으로 작성한다. 작성자와 다른 사람이 따로 검수하고 불일치는 토의로 정한다. 두 사람이 따로 라벨한 일치율을 기록한다.
- 합성 리뷰(`run.py absa synth`)는 **보조**로만 쓴다. 같은 모델이 쓰고 읽어서 정확도가 낙관적이고, 지시하지 않은 속성이 리뷰에 새어 들어가 정답이 불완전하다.
