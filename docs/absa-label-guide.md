# 속성 기반 감성분석(ABSA) 라벨 가이드 (의류 한정, 3단계) — 규칙 확정 v2 (2026-10-10)

이 문서는 Gemini 프롬프트(`review_analysis/absa.py`)와 사람이 직접 작성·검수하는 평가셋이 **같은 기준**을 쓰게 하려는 것이다.

**1차 확정 사항 (2026-10-08, 사용자 승인):** 속성 10개 그대로, 3단계 감성, 평가 표현 없는 사실 서술은 **미언급**(중립 아님), 중립은 '보통/무난/그저 그렇다' 평가이거나 장단점이 같은 비중일 때만. 이 기준이 `absa.py`의 프롬프트(`VERSION = 'v1'`)에 반영되어 있다.
**v2 (2026-10-10):** 평가셋 라벨링 중 갈린 사례를 4장의 번호 규칙(R1~R21)으로 확정했다. `absa.py`의 프롬프트도 같은 규칙으로 바꾸고 `VERSION = 'v2'`로 올렸다. 새로 애매한 사례가 나오면 규칙을 추가하고 `VERSION`을 올린다.

## 1. 출력 형식
리뷰 하나에서 **리뷰가 실제로 평가한 속성만** 뽑고, 속성마다 감성 1개를 붙인다.
```
[{"aspect": "재질·촉감", "sentiment": "부정"}, {"aspect": "배송", "sentiment": "긍정"}]
```
- 같은 속성은 리뷰당 한 번만 쓴다. 한 속성에 긍정과 부정이 섞이면 전체 뉘앙스를 따른다(결정이 안 되면 `중립`).
- 근거 문장(evidence span)은 운영 단계에서 추가한다(현재 시험에는 없음).

## 2. 속성 목록 (10개)

| 구분 | 속성 | 포함하는 것 | 예시 |
|---|---|---|---|
| 상품 | 재질·촉감 | 원단 종류, 두께, 촉감, 보온성, 비침 | "생각보다 얇고 까슬거려요" |
| 상품 | 사이즈·핏 | 사이즈 정확도, 길이, 품, 신축성 | "정사이즈인데 어깨가 좀 끼네요" |
| 상품 | 색상·디자인 | 색감(사진과 차이), 디자인, 스타일 | "사진보다 어두워요", "핏이 예뻐요" |
| 상품 | 품질·내구성 | 마감, 봉제, 올 풀림, 보풀, 튼튼함 | "한 번 입고 솔기가 터졌어요" |
| 상품 | 가격·가성비 | 가격 대비 만족, 비싸다/싸다 | "이 가격에 이 정도면 만족" |
| 상품 | 냄새 | 새 옷 냄새, 퀴퀴함, 화학 냄새 | "곰팡이 냄새가 나요" |
| 상품 | 세탁·관리 | 세탁 후 줄어듦·변형, 관리 편의 (물빠짐·이염은 품질·내구성, R4) | "한 번 빨았더니 줄었어요" |
| 서비스 | 배송 | 배송 속도, 배송 중 문제 | "주문 다음 날 도착" |
| 서비스 | 포장 | 포장 상태, 박스·비닐, 구김·오염 | "비닐이 찢어져 왔어요" |
| 서비스 | 교환·환불·CS | 교환/반품 절차, 고객센터 응대 | "반품 처리가 빨랐어요" |

- **상품 속성과 서비스 속성은 집계할 때 구분**한다(상품 문제는 MD/제조, 서비스 문제는 물류/CS 담당).
- 위에 없는 내용(예: 모델 착용 사진, 사은품, 브랜드 이미지)은 **뽑지 않는다**. 필요하면 속성을 추가하는 것을 결정한다.

## 3. 감성 3단계

| 감성 | 기준 |
|---|---|
| 긍정 | 그 속성에 만족/칭찬을 분명히 표현 |
| 부정 | 그 속성에 불만/문제를 분명히 표현 |
| 중립 | 그 속성을 평가했지만 "보통/무난/그저 그렇다", 또는 장단점이 같은 비중으로 섞임 |

- **평가 표현이 없는 단순 사실 서술**("택배 박스에 담겨 왔다", "비닐에 담겨 있었다")은 **미언급**으로 본다(중립이 아님). (1차 확정) 시험 결과 Gemini와 합성 리뷰 정답이 가장 많이 갈린 곳이 이 경계였다.
- **미언급은 출력하지 않는다.** "언급 안 함"과 "중립"을 섞지 않는다.

## 4. 판정 규칙 (번호가 있는 확정 규칙)
판단이 갈리면 이 번호로 근거를 말한다. 새로 갈리는 사례가 나오면 규칙을 **추가**하고 `VERSION`을 올린다(`absa.py`).

### 4-1. 어느 속성에 넣을지
| 규칙 | 내용 | 예 |
|---|---|---|
| R1 | 두께감, 도톰/얇음, 비침, 보온, 까끌/부드러움 → **재질·촉감** | "두께가 적당해서 좋아요" = 재질·촉감 긍정 |
| R2 | 길이·기장·총장·소매·품·핏·크롭·오버핏·크다/작다/끼다 → **사이즈·핏** | "기장이 짧게 떨어져서 마음에 들어요" = 사이즈·핏 긍정 |
| R3 | 색상, 워싱, 디자인, 스타일, 사진과 색 차이 → **색상·디자인** | "색 빠짐 느낌의 디자인이 예뻐요" = 색상·디자인 긍정 |
| R4 | 실밥, 먼지·보풀(털 날림), 올 풀림, 지퍼·단추·바느질·마감, 튼튼함, **이염·물빠짐·물듦** → **품질·내구성** | "같이 빨면 다른 옷에 색이 배어요" = 품질·내구성 부정 |
| R5 | 세탁 후 줄어듦·늘어남·구김·변형, 세탁·건조 관리 편의 → **세탁·관리** (물빠짐·이염은 R4) | "빨았더니 줄었어요" = 세탁·관리 부정 |
| R6 | 가격 대비 만족/불만 → **가격·가성비**. "가격 대비 품질이 좋다"처럼 품질도 평가했으면 **둘 다** 쓴다 | 가격·가성비 긍정 + 품질·내구성 긍정 |
| R7 | 택배 속도·배송 중 문제 → **배송**, 박스·비닐·구김·오염 → **포장**, 문의·응대·반품/교환 처리 → **교환·환불·CS** | |

### 4-2. 언급으로 칠지 (미언급 규칙)
| 규칙 | 내용 | 예 |
|---|---|---|
| R8 | 평가 표현 없는 사실 서술은 **미언급** | "택배 박스에 담겨 왔다" |
| R9 | **코디·조합 이야기**("이 옷이랑 맞춰 입을 게 없다")는 어떤 속성도 아니다 → 미언급 | 색상·디자인에 넣지 않는다 |
| R10 | **추측·가정·조언**("~할 것 같아요", "~일 수도 있어요", "~하셔요/추천해요")은 실제 경험이 아니므로 그 속성은 **미언급**. 실제 경험이 함께 적혀 있으면 그 경험으로 판단한다 | "보풀이 날 수도 있을 것 같아요" → 세탁·관리 미언급 |
| R11 | **과거·다른 구매 경험**은 제외하고 이번 구매 평가만 본다 | "작년에 같은 걸 사서 반품한 적 있는데 이번엔…" → 교환·환불·CS 미언급 |
| R12 | "다른 거 사세요", "강추" 같은 **추천 문구**는 속성이 아니다. 근거가 되는 속성은 본문 내용으로 따로 판단한다 | |
| R13 | 리뷰가 말하지 않은 속성을 **추론하지 않는다**("기분 상했다" → CS 아님) | |

### 4-3. 감성을 어떻게 정할지
| 규칙 | 내용 | 예 |
|---|---|---|
| R14 | **같은 속성 안에서 불만과 만족이 모두 있으면 중립** | "어깨는 크지만(불만) 기장은 딱 맞아요(만족)" → 사이즈·핏 중립 |
| R15 | 한쪽만 있으면 그쪽: "크긴 해요"만 있으면 부정, 만족만 있으면 긍정. **의도한 오버핏**이라 만족하면 긍정 | |
| R16 | **최종 평가를 따른다**: 기대와 달랐어도 마음에 든다고 하면 긍정, 반대도 같다 | "사진보다 어두운 색인데 오히려 마음에 들어요" → 색상·디자인 긍정 |
| R17 | **반어**는 실제 뜻으로 판단 | "포장이 너무 완벽해서 옷이 다칠 뻔했네요" → 포장 긍정 |
| R18 | "나쁘지 않아요", "생각보다 괜찮아요"는 약한 긍정. 확실하지 않으면 중립 | "가격치고 나쁘지 않네요" → 가격·가성비 긍정 |
| R19 | 비교("전에 산 것보다 두꺼워요")는 문맥상 좋은지 나쁜지로 판단 | |
| R20 | 한 속성은 리뷰당 한 번만 쓴다. 상충하면 R14를 따른다 | |
| R21 | 오타·ㅋㅋ·줄임말은 의미로 판단. 본문이 없으면 뽑을 속성 없음 | |

### 4-4. 평가셋 검수 때
- 사람과 모델이 다를 때는 **어느 쪽이 틀렸는지 규칙 번호로 판정**한다. 모델이 근거 있는 속성을 더 뽑았다면 사람 라벨이 빠진 것일 수 있다(예: 본문에 "품이 잘 맞는다"가 있는데 사이즈·핏 라벨이 없으면 긍정으로 보완).
- 규칙으로 정해지지 않는 사례는 임의로 고르지 말고 이 문서에 규칙을 추가한 뒤 라벨한다.

## 5. 평가셋 작성·검수 (사람이 직접)
- **법적 이유로 실제 리뷰를 복사하지 않는다**(`docs/korean-review-crawling-legal-notes.md`). 말투와 유형만 참고해 **새로 작성**한다.
- 규모: 200~300건. 속성별 최소 25건 언급(서비스 속성 포함), 감성은 속성마다 긍정·부정·중립이 모두 들어가게 한다.
- 말투 다양화: 짧은 반말, ㅋㅋ/ㅠㅠ, 오타, 정중한 장문, 반어, 줄임말, 복합 속성.
- 라벨은 `docs/absa_eval_template.csv`의 **긴 형식**(리뷰 1건에 속성 1행)으로 작성한다. 작성자와 다른 사람이 따로 검수하고 불일치는 토의로 정한다. 두 사람이 따로 라벨한 일치율을 기록한다.
- 합성 리뷰(`run.py absa synth`)는 **보조**로만 쓴다. 같은 모델이 쓰고 읽어서 정확도가 낙관적이고, 지시하지 않은 속성이 리뷰에 새어 들어가 정답이 불완전하다.
